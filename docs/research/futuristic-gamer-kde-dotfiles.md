# Red Glass and Neon: Futuristic Gamer KDE Dotfiles for the ASUS TUF Gaming F15

For an ASUS TUF Gaming F15 running CachyOS, KDE Plasma 6.8 on Wayland, and Plasma Login Manager (PLM), two primary architectural options stand out. The first is **NEONGRID**, recolored to red: built and benchmarked specifically on CachyOS + Wayland, it supports `plasmalogin` styling and deploys the highest-fidelity blur stack: Better Blur DX, Darkly, Klassy, and Panel Colorizer ([NEONGRID](https://github.com/cromewar/neongrid)). The second is **Crimson Glass**, the most complete out-of-the-box red/black "ROG-style" suite and the only package featuring an explicit patch for Plasma 6.8 ([Crimson Glass](https://github.com/SirFork1988/Crimson-Glass)). No maintained native "ROG" global theme exists for Plasma 6—neither on the KDE Store nor across GitHub. Consequently, an authentic Republic of Gamers visual identity must be engineered modularly using crimson accent styling, red icon assets, the ASUS ROG GRUB theme, and `asusctl`. The benchmark compositor blur engine in 2026 is **Better Blur DX 2.6.0**, which provides documented Plasma 6.8 compatibility ([Better Blur DX releases](https://github.com/xarblu/kwin-effects-better-blur-dx/releases)). The alternative, **Glass**, introduces advanced optical shaders (tinting, chromatic glow, edge illumination, Snell refraction), though its Plasma 6.8 upstream fix was merged only recently ([Glass](https://github.com/4v3ngR/kwin-effects-glass)). Three hardware and platform constraints govern this setup: since Plasma 6.7, KWin exhibits a tendency to bind compositing to the discrete RTX 3050 GPU on hybrid laptops; all compiled out-of-tree C++ KWin plugins break on minor Plasma ABI updates; and **Plasma Login Manager completely ignores legacy SDDM themes**, which most community rices still ship. Because most custom cyberpunk dotfiles are single-author projects with modest community testing, scrutinizing install scripts and executing `--dry-run` modes prior to deployment is mandatory.

## The Maximum-Fidelity Blur Stack: Five Distinct Layers, One Engine

Frosted glass in Plasma 6 cannot be achieved via a monolithic theme; it requires an integrated multi-layer pipeline. The foundational layer is the **compositor blur engine**: native KWin Blur, **or** Better Blur DX, **or** Glass. These are strictly mutually exclusive; native KWin blur must be disabled if either third-party plugin is active ([Better Blur DX](https://github.com/xarblu/kwin-effects-better-blur-dx); [Darkly](https://github.com/Bali10050/Darkly)). The original taj-ny `kwin-effects-forceblur` was **archived in November 2025**, and dependent links (such as Mystical Blue) are dead ([taj-ny](https://github.com/taj-ny/kwin-effects-forceblur)). Better Blur DX is its active open fork, providing per-window-class regex matching, brightness, contrast, saturation, corner radius controls, and optical refraction; it maintains ~700 stars and an active AUR package (`kwin-effects-better-blur-dx` 2.6.0). Glass adds **color tinting, bloom glow, specular edge lighting, and physical Snell refraction**, with independent blur and noise radii for docks, window decorations, and client content. It currently exists only as `kwin-effects-glass-git`, requiring manual compilation from git to track recent Plasma 6.8 fixes ([Glass](https://github.com/4v3ngR/kwin-effects-glass)). Neither fork preserves the legacy "static blur" caching mode (which reduced GPU draw significantly) due to upstream architectural changes introduced in Plasma 6.5 ([Better Blur DX](https://github.com/xarblu/kwin-effects-better-blur-dx)).

Above the blur engine sits the **application widget style**, responsible for rendering translucent background surfaces. One option is **Darkly** (a modern C++ fork of Lightly, `darkly-bin` 0.5.41), which does not blur surfaces internally but delegates shader composition to the active KWin blur engine while following system color schemes dynamically ([Darkly](https://github.com/Bali10050/Darkly)). The alternative is **Kvantum** 1.1.8 (native in CachyOS repositories) paired with a translucent SVG style. The third layer is **window decorations**. **Klassy** (`klassy` 6.7.3; master branch requires Plasma 6.6+) renders accent-colored outlines and tinted drop shadows, delivering the neon glow characteristic of cyberpunk interfaces ([Klassy](https://github.com/paulmcauley/klassy)). SVG-based Aurorae alternatives survive Plasma ABI upgrades without rebuilding but suffer from fractional scaling rasterization defects ([Lemmy Discussion](https://lemmy.korz.dev/post/596956)). The fourth layer is **KDE-Rounded-Corners**, packaged in the `cachyos` repository (0.10.0) and rebuilt against system libraries. It provides outline smoothing, though it is partially redundant if Better Blur DX or Glass handles corner clipping ([Rounded Corners](https://github.com/matinlotfali/KDE-Rounded-Corners)). The fifth layer is **Panel Colorizer** 8.0.0, which generates floating widget islands, glowing borders, and dynamic presets that **automatically transition panels to opaque solid fills when windows are maximized or full-screened**, adding merely 0.5–1.0% idle CPU overhead. Its optional C++ blur plugin can destabilize KWin across minor desktop upgrades and should be verified carefully ([Panel Colorizer](https://github.com/luisbocanegra/plasma-panel-colorizer)).

Three compositor settings dictate whether translucency appears deep and frosted or washed out:
1. **Disable KWin Native Translucency:** The built-in `translucency` effect desaturates third-party blur passes. Window opacity should instead be controlled via KWin Window Rules ([Glass](https://github.com/4v3ngR/kwin-effects-glass)).
2. **Disable Background Contrast:** KWin's built-in `contrast` effect distorts dark surfaces, shifting deep `#1c1c1c` tones toward hazy, washed-out grays ([Better Blur DX](https://github.com/xarblu/kwin-effects-better-blur-dx)).
3. **Wayland Protocol Transition (`ext-background-effect-v1`):** In Plasma 6.7, KWin deprecated `org_kde_kwin_blur_manager` in favor of the standardized Wayland `ext-background-effect-v1` protocol. Applications that do not explicitly request the new protocol fail to register client-side blur under native KWin, making Better Blur DX's window-class regex forcing essential ([Better Blur DX PR #8](https://github.com/xarblu/kwin-effects-better-blur-dx/pull/8); [Wayland Protocols](https://wayland.app/protocols/ext-background-effect-v1)).

## Three Platform Traps on the ASUS TUF F15: dGPU Binding, ABI Invalidation, and Login Theming

1. **KWin Binding to Discrete GPU on Hybrid Hardware:**
   Starting in Plasma 6.7, KWin Wayland may bind its EGL/Vulkan presentation context to the discrete NVIDIA GPU (`/dev/dri/renderD129`) rather than the Intel integrated GPU (`renderD128`). When this occurs, KWin draws **~6 W of continuous idle dGPU power**, preventing the RTX 3050 from entering Runtime D3 (RTD3) sleep and unnecessarily elevating fan noise. This misbehavior can be verified via `nvidia-smi`: if `kwin_wayland` appears in the process list, the compositor is trapped on the discrete chip. Placing `KWIN_DISABLE_VULKAN=1` in `~/.config/plasma-workspace/env/kwin.sh` forces KWin to remain on OpenGL compositing pinned to the Intel iGPU ([KDE Discuss](https://discuss.kde.org/t/kwin-runs-on-dgpu-instead-of-igpu-in-hybrid-graphics-laptop/31415); [NVIDIA Developer Forums](https://forums.developer.nvidia.com/t/nvidia-gpu-does-not-go-to-sleep-in-hybrid-mode-kde-plasma-wayland/303498)).

2. **C++ ABI Breakage Across Plasma Minor Upgrades:**
   Out-of-tree C++ compositor plugins (`kwin-effects-better-blur-dx`, `klassy`, and Panel Colorizer's C++ helper) link against internal KWin private headers. Minor version upgrades (e.g., 6.8.0 to 6.8.1) alter internal virtual method tables, causing plugins to fail to load or crash `kwin_wayland` during session startup ([Better Blur DX PR #8](https://github.com/xarblu/kwin-effects-better-blur-dx/pull/8)). To guarantee system resilience, automated pacman post-transaction hooks (matching NEONGRID's design) must recompile out-of-tree plugins automatically whenever `kwin` is updated.

3. **Plasma Login Manager (PLM) Replaces SDDM Theming:**
   Plasma 6 introduces Plasma Login Manager (`plasmalogin`), which locks down display greeter rendering and completely ignores QML SDDM theme packages ([CachyOS Forum](https://discuss.cachyos.org/t/plasma-login-manager-customization-in-plasma-6/5021)). Suites advertising "complete SDDM integration" (including Crimson Glass and Sweet KDE) leave the actual login screen unthemed under PLM. In PLM, visual cohesion is achieved through the system color scheme and wallpaper engine plugins (`WallpaperPluginId`), such as Smart Video Wallpaper Reborn, which apply synchronously to both the desktop session and the login greeter ([NEONGRID](https://github.com/cromewar/neongrid); [SVWR](https://github.com/luisbocanegra/plasma-smart-video-wallpaper-reborn)).

## Gaming Performance: Direct Scanout, Opaque Panel Transitions, and iGPU Offloading

Compositor blur requires multiple render target passes, downsampling, and dual-filtering shaders. When 3D games run in exclusive fullscreen mode on Wayland, KWin engages **Direct Scanout**: the client application surface is handed directly to the hardware display controller, completely bypassing desktop compositing and reducing the GPU cost of frosted-glass shaders to **zero** ([KWin Direct Scanout Documentation](https://invent.kde.org/plasma/kwin/-/wikis/Direct-Scanout); [Linuxiac](https://linuxiac.com/kde-plasma-6-7-3-restores-triple-buffering-for-nvidia-gpus/)).

However, when games run in borderless windowed mode, or when desktop overlays (MangoHud, notifications) break direct scanout, translucent blurred panels must be re-composited on every single frame ([CachyOS Forum](https://discuss.cachyos.org/t/direct-scanout-is-not-turning-on/31826/2)). To protect frame pacing under these conditions:
- Launch games via `prime-run %command%` to render on the discrete RTX 3050 while KWin compositing stays confined to the Intel integrated GPU.
- Configure Panel Colorizer with dynamic visibility rules that toggle panel blur to solid opacity whenever maximized windows or fullscreen surfaces are detected ([Panel Colorizer](https://github.com/luisbocanegra/plasma-panel-colorizer)).
- For animated wallpapers, configure Smart Video Wallpaper Reborn to automatically pause playback during window maximization or fullscreen execution, utilizing its low-battery threshold to suspend video decoding and blur shaders entirely ([SVWR](https://github.com/luisbocanegra/plasma-smart-video-wallpaper-reborn)). Ensuring video decoding routes via Intel VA-API prevents waking the discrete GPU.
- When deploying NEONGRID's animated GLSL wallpaper shader, cap rendering to 30 FPS and disable dynamic accent color sampling from the wallpaper canvas ([NEONGRID](https://github.com/cromewar/neongrid)).

## Concrete Deployment Blueprint for the ASUS TUF Gaming F15

**Primary Architecture: NEONGRID with Crimson Palette Shift.**
NEONGRID is the only candidate suite verified on CachyOS, Wayland, and Plasma Login Manager. It deploys the full blur stack (Better Blur DX with window-class regex matching, Darkly, Klassy with accent glow, and Panel Colorizer) and includes automated pacman rebuild hooks. Its centralized `palette.sh` architecture allows recoloring all desktop components simultaneously, transforming its default neon-green palette into ROG crimson without modifying individual subsystem configs ([NEONGRID](https://github.com/cromewar/neongrid)).

Recommended deployment sequence:
1. Verify `nvidia-smi`. If `kwin_wayland` is bound to the discrete GPU, export `KWIN_DISABLE_VULKAN=1` in `~/.config/plasma-workspace/env/kwin.sh`.
2. Install `kwin-effects-better-blur-dx` 2.6.0 from the AUR; verify that native KWin Blur, Translucency, and Background Contrast effects are disabled in System Settings.
3. Execute NEONGRID's installer with `--dry-run` to inspect target paths, capture a Snapper filesystem snapshot, and proceed with full installation.
4. Install `kwin-effect-rounded-corners` from the native CachyOS repository if secondary geometry smoothing is desired.
5. For PLM login visual continuity, configure Smart Video Wallpaper Reborn with an ASUS ROG hardware animation decoding via Intel VA-API.
6. Complete ROG hardware branding: deploy `grub-theme-asus-rog`, configure Papirus icons via `papirus-folders -C red` (or Tela red-dark), set Bibata cursors, and configure keyboard RGB illumination via `asusctl` ([AUR grub-theme-asus-rog](https://aur.archlinux.org/packages/grub-theme-asus-rog); [AUR papirus-folders](https://aur.archlinux.org/packages/papirus-folders)).
7. Export the resulting configuration as a custom global theme via Plasma 6's native theme export utility ([Linuxiac](https://linuxiac.com/kde-plasma-6-6-lets-users-create-custom-global-themes/)).

**Alternative Architecture: Crimson Glass.**
Best suited for environments requiring a pre-packaged crimson/carbon aesthetic verified on Plasma 6.8 with built-in gaming opacity rules. Replace its stock blur implementation with Better Blur DX, and note that its SDDM login component will not render under PLM ([Crimson Glass](https://github.com/SirFork1988/Crimson-Glass)). Glass remains an advanced shader upgrade once upstream Plasma 6.8 patches are tagged in the AUR package.

## Conclusion

In modern KDE Plasma 6.8 on Wayland, monolithic global themes are obsolete: maximum-fidelity frosted glass depends on out-of-tree compiled compositor shaders, while display manager theming has shifted entirely to Plasma Login Manager. The most robust configurations are not those that look best in static screenshots, but those that **automate plugin recompilation on system upgrades and accommodate PLM architecture**. Genuine ROG branding cannot be downloaded as a single bundle—it must be constructed modularly with crimson accent styling over a stable, hardware-isolated blur pipeline.
